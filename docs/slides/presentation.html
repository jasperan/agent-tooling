the problem with existing frameworks

Why Agent Tooling?

ProblemWhat Happens
Provider Lock-inStuck with one LLM vendor. Switching means rewriting everything.
Unsandboxed ExecutionTools run directly on the host. One bad exec() and it's over.
No InteropAgent systems can't share tools. Every framework is an island.

The @tool Decorator

Define a tool once. Get Python, OpenAI function calling, and MCP schemas for free.

tools/custom.py
@tool(name="greet", category="custom")
def greet(name: str, formal: bool = False) -> str:
"""Generate a greeting."""
if formal:
return f"Good day, {name}."
return f"Hey {name}!"

Auto-Generated Schemas

OpenAI Format

schema = greet.to_openai_function()
# {
# "name": "greet",
# "parameters": {
# "name": {"type": "string"},
# "formal": {"type": "boolean"}
# }
# }

MCP Format

mcp = greet.to_mcp_tool()
# {
# "name": "greet",
# "inputSchema": {
# "name": {"type": "string"},

Tool Registry

Global singleton. Every @tool auto-registers. Zero manual wiring.

registry.py
from agent_tooling import ToolRegistry
# List all tools (including pi-dev imports)
for tool in ToolRegistry.list_tools():
print(f"{tool['name']}: {tool['description']}")
# Get schemas for function calling
schemas = ToolRegistry.to_openai_functions()

Multi-Provider LLM Support

Powered by OpenHands SDK. One syntax, six providers.

agents/base.py
# Local Ollama (default, no API key)
agent = BaseAgent(model="ollama/qwen3-coder")
# Anthropic Claude
agent = BaseAgent(model="anthropic/claude-sonnet-4")
# OpenAI, Google, Mistral, Groq...
agent = BaseAgent(model="openai/gpt-4o")
agent = BaseAgent(model="groq/llama-3.3-70b")

Ollama is the default. No API key needed. Everything runs local.

Docker Sandboxing

Mark tools with sandbox_required=True. They run inside containers automatically.

sandboxed_tool.py
@tool(name="run_untrusted", sandbox_required=True)
def run_untrusted(code: str) -> str:
exec(code)
return "executed"
# Agent with Docker workspace
agent = BaseAgent(
model="ollama/qwen3-coder",
workspace=DockerWorkspace(image="python:3.12-slim"),
)

Pi-dev Bridge

Bidirectional tool exchange. No TypeScript dependencies required.

Direction 1: Serve tools TO pi-dev

config = bridge.get_mcp_config()
# Pi-dev discovers tools via MCP

Direction 2: Import pi-dev tools

imported = bridge.consume_pidev_tools()
# ["pidev_read", "pidev_write", ...]

Adding Custom Tools

Create the function. Decorate it. It's available everywhere, instantly.

tools/custom/my_tool.py
@tool(name="my_tool", category="custom",
mcp_enabled=True, sandbox_required=False)
def my_tool(param1: str, param2: int = 0) -> dict:
"""Description of what this tool does."""
return {"result": f"Processed {param1}"}

Available in: Registry • MCP Server • HTTP API • Agent Sessions
